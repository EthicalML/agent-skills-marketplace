# Reconstruct an asset from images

1. Define the asset's intended use before choosing a method: a static sculpture, a background prop, or a deforming character. Preserve the original reference images. Inspect silhouette, proportions, facial volumes, hands, material boundaries, and hidden surfaces. Different screenshots are not calibrated multiview inputs; do not describe independent single-image generations as multiview reconstruction.

2. Choose an actual image-to-3D backend or a modeling workflow capable of the reference detail. Check supported hardware, available memory and disk, checkpoint availability, component licenses, and any service credentials or charges before a large download. For a tested local Apple Silicon route, read [local-image-to-3d.md](local-image-to-3d.md). Record the runtime revision, checkpoint identifier, input, seed, resolution, and settings. The Blender connection executes and inspects geometry; it does not itself reconstruct geometry from images. A missing backend is not a reason to present a primitive character as a finished likeness.

3. Prepare foreground alpha using the chosen backend's documented preprocessing. Save it separately from the original and inspect it: preserve thin tails, fingers, ear edges, and gaps between limbs; remove floors and interface elements. An incorrect mask changes the inferred shape. Do not silently replace the reference with a generated reinterpretation.

4. Generate a modest-resolution candidate with the backend's normal quality settings. Save logs and terminal status. Keep the raw mesh unchanged and render it before scheduling expensive refinements. If the backend has no progress output, add stage timing around its public workflow or inspect the running process before diagnosing a stall; GPU work may show little CPU usage. Do not launch overlapping GPU-heavy jobs on memory-constrained machines.

5. Render front, three-quarter, side, back, and detail views with one neutral clay material and consistent camera scale and lighting. Open the images. Compare silhouette and landmark proportions with the source; inspect muzzle depth, mouth cavity, eyelids, glove fingers, shoe shape, and inferred back surfaces. Texture likeness alone does not pass the geometry gate. Record specific defects and select one next intervention: better masking, another input view or seed, increased reconstruction resolution, or targeted sculpting. Keep comparable before/after renders. Increased polygon count is not evidence of improved likeness.

6. If clay renders show striping or dark specks, inspect face winding, duplicate faces, boundary edges, and non-manifold edges before smoothing or regenerating. On a copy, test a normals-only repair and render with identical lighting. Imported OBJ custom normals can override smooth shading; inspect or clear them for the neutral review before blaming visible faceting on vertex geometry. Preserve intentionally authored normals in production assets. This can fix shading while leaving holes, self-intersections, and invented geometry untouched; report those separately. A backend successfully exporting an OBJ does not prove its mesh is clean. Test decimation on a copy too: it can turn small reconstruction defects into large tears. When replacing a part, constrain the removal to that part and inspect adjacent clothing, feet, and facial structures from oblique views before accepting the cut. Do not apply blanket voxel remeshing to an open or inconsistently oriented mesh without a comparison render: it can destroy entire regions rather than repair them.

7. If the selected reconstruction remains visibly rough or needs reusable deformation, read [asset-polish.md](asset-polish.md) and follow its regional rebuild, retopology, and quality gates before another final render. Classify the selected result honestly. A detailed triangulated sculpture can be a useful static asset while still failing animation requirements. For a deforming character, inspect connected components, hidden bridges between fingers or limbs, mouth/eye separation, topology around joints and expressions, and surface noise. Retopologize and separate parts where required; create UVs/materials (or named rest-space vertex colors for a simple palette), a skeleton, weights, and facial controls. Test bent elbows/knees, hand poses, blink, mouth shapes, and the intended contacts before calling it animation-ready. For rebuilt fingers or other separated forms, inspect every intended gap. Zero non-manifold edges can coexist with incorrectly fused digits; compare connected components and Euler characteristic against the intended topology (a closed, connected glove without holes should have Euler characteristic 2). Keep thin gaps several remesh voxels wide and recheck after smoothing/subdivision. Automatic weighting alone is not verification.

8. Save an editable .blend, export the selected asset, and reimport in an isolated scene. Include neutral review images and provenance beside the output. Report what was actually generated, what was changed, visible remaining defects, and which readiness tests passed. Keep backend weights and private reference images outside the skill repository.
