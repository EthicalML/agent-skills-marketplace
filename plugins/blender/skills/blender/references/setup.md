# Setup

1. Locate the Blender executable and version. On macOS the usual executable is `/Applications/Blender.app/Contents/MacOS/Blender`; otherwise use the installed `blender` binary. The external helper needs Python 3.10+ and only its standard library. The upstream add-on also imports `requests` inside Blender; if enabling it reports a missing dependency, install requests using that Blender installation's Python, not the external client's Python.

2. Stage the checksum-pinned add-on with `python3 <skill>/scripts/setup.py --addons-dir <absolute staging directory under project/tmp>`. In Blender Preferences → Add-ons → Install from Disk, select the resulting `blender_mcp.py`, enable it, and save preferences. Alternatively pass the actual Blender user scripts/addons directory to setup.py. It backs up a different existing file once and refuses to overwrite an existing backup. If Blender was already open when its scripts/addons directory was created, save work and fully quit/reopen Blender before enabling it; otherwise it may list the add-on but report "No module named blender_mcp". Re-enable the add-on after replacing it. The source is pinned to commit `35de9ba202a5dc212b139820eef9f9d999a2edb2` of https://github.com/ahujasid/mcp-for-blender; attribution is in [upstream-license.txt](upstream-license.txt).

3. In the 3D Viewport sidebar (N), open MCP for Blender and start/connect its listener. Despite that label, this workflow does not launch an MCP server. Keep the listener on localhost. It executes trusted Python with Blender's permissions, has no authentication, and is not a sandbox. Upstream MCP-server safe mode is not in this path. Leave telemetry disabled; the helper contains no telemetry uploader. External asset services are optional.

4. Run `python3 <skill>/scripts/blender.py status`. Check the Blender version and protocol (pinned add-on protocol 9), then inspect the scene and capture a screenshot. If connection is refused, check that the GUI listener is running and the port matches `BLENDER_PORT`. A headless Blender process is not a substitute for this GUI listener. A viewport screenshot needs an actual 3D View area. If a protocol differs, report it and test required commands before assuming compatibility.

5. To enable the skill in Codex during local development, copy this entire skill directory to `${CODEX_HOME:-$HOME/.codex}/skills/blender`, preserving scripts and references. Do not overwrite an existing skill without checking its origin and local changes. Installed copies must be refreshed after source changes. In a new session verify that `blender` appears, then use its installed absolute path. Other compatible runtimes can install the marketplace's `blender` plugin normally.
