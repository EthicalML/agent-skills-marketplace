# Character interaction and video

1. Write a short beat sheet before modeling: what causes each action, which objects touch, frame ranges, camera cuts, and the final delivery duration/FPS. Build reusable character and prop collections with named roots and joint pivots. Use a rig or hierarchical transforms according to the motion; do not imply a collection of animated primitives is a production character rig.

2. Block contact poses before polishing. Measure hand-to-handle positions in the same world space at the actual contact frames. Account for parent transforms and the contact point inside the hand, not just its object origin. For rolling objects, compare their surface against the track plane; a sphere's vertical offset on a slope differs from its radius. Add visible mechanisms when a bounce or release would otherwise appear uncaused.

3. Validate the frames between poses too. Independently interpolated position channels can drift off a surface even when every authored key is correct. Sample the whole contact interval, then constrain or bake the corrected path when needed. Keyframe release, anticipation, contact, and settling explicitly. Check that a grasp follows its moving target rather than touching it at only one instant.

4. Render and open representative wide shots, closeups, contact frames, and frames on both sides of camera cuts. Inspect silhouettes, occlusion, penetration, floating feet, and whether the action reads at delivery resolution. For narration or sound effects, generate the audio first, measure its duration, and place complete phrases and effects against the same frame/FPS timeline. Use an available speech skill if requested; keep its original output alongside the mix.

5. Benchmark a final-quality frame before the full sequence. For Cycles GPU rendering, enumerate devices and enable an available device in the background process; GUI preferences alone do not establish the worker's device. A first render can include shader compilation, so measure a second frame too. Record engine, resolution, samples, device, and timing. Keep heavy jobs sequential unless the machine can support more.

6. Render an image sequence through the background job runner, then encode video and mix audio with an available encoder. Keep the saved input and render script immutable during the job. Resume only frames from the same scene/script/settings revision; after an input change, use a new sequence directory or invalidate the affected frames. Check the complete expected frame set, decode the finished video, and verify resolution, frame count, FPS, duration, and audio stream. Inspect sampled frames from the encoded video; do not describe image inspection as having watched or listened to the whole movie.

7. Package the editable project, reusable assets, video, audio/captions, build scripts, source/license notes, and validation report. A file written by `bpy.data.libraries.write` is a data library and can open to an empty startup scene. For a directly openable project, reopen it in a separate process, select the intended scene, and save with `bpy.ops.wm.save_as_mainfile`; verify the default scene on another reopen. Keep unrelated user scenes out of the delivered file while preserving them in the working session. Pack or include audio as well as images.

8. For animated glTF assets, inspect the exporter schema and choose the animation grouping deliberately. Blender's default `ACTIONS` mode emits separate object actions; a coordinated multi-object performance may require `export_animation_mode="SCENE"` or `"ACTIVE_ACTIONS"` through a task-specific bpy export script. In Blender 5.2, scene mode also defaults `export_anim_scene_split_object` to true; disable it when a single clip is required. Check the clip count and sample imported world transforms and evaluated mesh bounds at rest, maximum reach, and facial-action frames. In a tested skinned character, object-scale eye blinks were omitted while the armature clip exported successfully; moving the blink to eye-bone animation preserved it. Verify the actual blink after reimport rather than treating a nonempty clip as proof that every action survived. When stretching a limb, check child scale inheritance so the hand retains its proportions, and verify that behavior after export too. A tested nonuniform parent scale with disabled child scale inheritance introduced shear that glTF joint TRS could not reproduce. Baking evaluated pose matrices into independent joints in the isolated export copy preserved the motion; keep the original editable hierarchy in the blend. Compare world-space bounds computed from evaluated vertices, since transforming a local bounding box can overestimate bounds after rotation. Convert required curve geometry to mesh in that isolated export process so smiles, cables, or springs are not omitted; retain the editable originals in the blend.

9. Record actual failures, corrections, render cost, and unverified limits. Distinguish technical contact/export checks from artistic quality and temporal smoothness. Retain useful previews and job logs under ignored project tmp so another run can examine the evidence.
