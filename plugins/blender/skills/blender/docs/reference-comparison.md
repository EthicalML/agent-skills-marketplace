# Compare with a reference model

Use this workflow when a user provides or requests a 3D reference for likeness, proportions, or multi-angle review. It is also useful for comparing successive local checkpoints. A tested checkpoint comparison is not evidence that an external source model has been acquired or matched.

1. Acquire the source through its authorized download flow. Record author, source URL, asset license, file hash, and acquisition date. If the endpoint requires credentials, request configuration in the service/add-on or a local file path; do not ask for secrets in chat. Continue independent setup/versioning work, but mark actual source inspection as blocked until a mesh exists. Thumbnail discovery, download, import, and geometry inspection are separate states.
2. Preserve the accepted working model and import the reference into a separate collection/scene with automatic script execution disabled. Select the intended source scene explicitly when a blend contains multiple scenes. Exclude scene props, floors, lights, and cameras from model bounds. Preserve parent/armature relationships and associated materials/resources.
3. After linking appended objects into the working scene, update the dependency graph before reading world matrices or reparenting. A tested append initially scattered eyes, ears, and nose because transforms were stale. Inspect the imported asset as a whole before trusting measurements. Reopen the saved comparison and check that attachments remain intact.
4. Normalize orientation, uniform scale, and ground height, and record transforms. Do not stretch axes independently to force agreement. Whole-body height is a useful starting point for matching poses, but bent knees, tilted heads, or different ear conventions require named anatomical landmarks instead. State uncertainty rather than treating overall bounds as recovered anatomy.
5. Capture front, rear, profile, and three-quarter orthographic views with fixed projection and scale. Place models along the camera's screen-right axis for each view so profiles do not overlap. Label candidate/reference identity clearly. A shared lighting rig does not guarantee identical illumination at different positions; use centered individual captures or controlled uniform lighting for material judgments.
6. Compare skull/ear height, eye spacing, muzzle depth, shoulder width, torso length, hand size, leg length, and shoe proportions. Mark pose-dependent ratios. Change one region of the working candidate and repeat the same views. Do not silently modify the reference or interpret smoother surfaces as better proportions.
7. Record results and rejected attempts. In the local checkpoint trial, rear/profile views exposed cleaned shoulder flaps but also changed shoe proportions. Blend append, normalization, and four-view comparison were tested; external-reference matching and other importer branches were not. Keep such boundaries explicit when documenting capability.
8. Version scripts, selected views, and learnings with each accepted iteration. Store large editable checkpoints in a versioned binary store or release, record checksums/restore paths, and verify remote uploads. Ignoring .blend files in Git is not a backup. Preserve the direct rebuild input and track third-party redistribution separately from the working model.

## Findings from an acquired external blend

1. Inspect every archive level before import. A tested download contained a ZIP inside the outer ZIP; the editable blend and matching textures were in the nested archive. Check extraction paths stay inside the chosen project directory. Record the original archive hash and preserve the source.
2. Pack or resolve images actually used by material nodes. Old source files can contain unrelated brush/reference-image paths from another computer; distinguish those from missing render dependencies. Test the original supplied pose before changing a rig to rest mode.
3. Keep rest-pose conversions as labeled derivatives. In the observed asset, the supplied pose rendered correctly but rest mode occluded the pupils. Rest geometry helped with torso dimensions but was not a faithful appearance reference. Same world camera direction does not align anatomical directions when the source character is turned or leaning.
4. For quantitative fitting, measure evaluated vertices transformed to world space. Transforming local bounding-box corners is only a conservative bound and can overestimate rotated parts. In a trial this underestimated the required ear scale. Compare before/after measurements and the rendered silhouette, not just a bounding-box score.
5. Frame from measured model widths plus group separation. A wider reference can clip hands even when the earlier checkpoint comparison fit. Offer an interactive-only save path so loading a new pair does not require rendering every view.
6. Keep experimental fittings separate from accepted models. A static trial improved head/ear/body proportions and matched several regional extents closely, while muzzle shape and shoe/ankle shape still differed. A close numerical extent match is not a likeness pass, and baking a static trial is not rig transfer.

Evidence now includes one externally acquired blend with packed material textures, original-pose visual inspection, labeled rest-derived measurements, four-angle comparison, and two bounded static fitting trials. This does not establish automatic reference matching, neutralization of arbitrary rigs, other importer formats, or production facial topology.
